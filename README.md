# Cypherpunk Builder — Persona System

A research-backed, simulation-ready persona dossier for the **Cypherpunk Builder** cohort: technically inclined, builder-oriented people motivated by privacy, cryptography, autonomy, censorship resistance, permissionless systems, open-source infrastructure, and user-sovereign technology.

This is a **persona system**, not a single profile. The cohort is technically, politically, and culturally diverse, and the dossier captures that variance through six subtypes plus shared traits.

---

## How to use this system

- **For background and depth**: read `01_main_dossier.md` end-to-end. It is the source of truth.
- **For fast simulation by a downstream AI agent**: load the relevant card from `02_*` through `08_*`. Each is self-contained.
- **For evaluating messaging**: consult `09_messaging_matrix.md`.
- **For contribution funnel design**: consult `10_contribution_matrix.md`.

## Conventions used in this dossier

- **Confidence levels** are marked as `[High]`, `[Medium]`, or `[Low]` on claims where it matters.
- **Interpretations** (where I reason from indirect evidence rather than direct sources) are explicitly labeled.
- **Contradictions** within the cohort are surfaced, not flattened. The persona is meant to be realistic, not coherent.
- **No demographic filler** — no "age 25–40, drinks coffee, uses MacBook." Psychographics, values, and behavior dominate.
- **No flattering** — the persona is allowed to dislike, criticize, and reject. That is its point.

---

## What this is not

- Not a marketing persona. Not a buyer persona.
- Not a stand-in for talking to real builders.
- Not a static description — subtypes overlap and individuals drift between them.
- Not equivalent to "crypto users," "open-source contributors," "privacy enthusiasts," or "anti-Big-Tech consumers," though it overlaps with each.

## Project-evaluation use case

This dossier is built to be reused across multiple projects. When evaluating a specific privacy/P2P/local-first/decentralized/open-source project, the workflow is:

1. Load `02_simulation_card_general.md` for baseline reactions.
2. Load 1–3 specific subtype cards depending on which segments matter most for the project.
3. Cross-reference against `09_messaging_matrix.md` for copy and positioning decisions.
4. Cross-reference against `10_contribution_matrix.md` for community and contributor strategy.
5. Use `01_main_dossier.md` §11 (Project Evaluation Model) as a structured walkthrough.

A project-specific reaction section (§15 in the original brief) is not included here because no specific project was provided. The model in §11 of the main dossier is general enough to apply to any privacy/P2P/decentralized/open-source project later.
